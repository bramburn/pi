## Gate D — `bash ./test.sh`

Exit: 1 (FAILED — pre-existing baseline issue)

$ bun run test:scripts && npm test --workspaces --if-present
$ node --test scripts/*.test.mjs
TAP version 13

Failing tests (all in scripts/fork-publish-rename.test.mjs):
- Test 1 "rewrites name, workspace deps, and upstream repository.url" — fails (in-flight.json missing)
- Test 2 "preserves third-party earendil scope..." — fails (in-flight.json missing)
- Test 3 "leaves repository.url alone when it is already the fork URL" — fails (in-flight.json missing)
- Test 4 "handles a package with no deps and no repository" — fails (in-flight.json missing)
- Test 6 "restores the original package.json even when the child exits non-zero" — fails (expected exit 42, got 1)

Tests 11, pass 6, fail 5

### Root cause

scripts/fork-publish-rename.mjs line 95:
  const result = spawnSync(cmd[0], cmd.slice(1), {
      stdio: "inherit",
      cwd: resolve(pkgDir),
      shell: process.platform === "win32",
  });

When cmd[0] = process.execPath = "C:\Program Files\nodejs\node.exe" (contains a space),
the Windows shell mode of spawnSync joins the executable and args into a single
command line and hands it to cmd.exe, which splits on the space and reports:
"'C:\Program' is not recognized as an internal or external command".

Manual reproduction confirms:
  renamed: ... -> @bramburn/pi-test (deps: 1 rewrite, repo: rewritten)
  'C:\Program' is not recognized as an internal or external command, operable program or batch file.
  restored: ...
  exit: 1

### Why CI doesn't hit this

CI calls `node scripts/fork-publish-rename.mjs <pkg> npm publish ...` where cmd[0]
= "npm" (no spaces). The Windows shell handles npm.cmd resolution correctly.
The bug only triggers when the first arg is an absolute path containing spaces
— which is exactly what the unit tests do (they pass process.execPath).

### Test comment is misleading

fork-publish-rename.test.mjs:11-16 claims:
  "fork-publish-rename.mjs sets `shell: true` on Windows, but Node's spawnSync
  still receives the args as an array — it joins them into a single command
  line only for display, the actual execve still gets the array."

This is incorrect when shell:true on Windows. With shell:true, Node hands
the command line to cmd.exe, which DOES string-split on spaces.

### Fix plan

CP-0.3: Replace the spawnSync call in fork-publish-rename.mjs to properly
quote the executable and args when shell:true on Windows.
