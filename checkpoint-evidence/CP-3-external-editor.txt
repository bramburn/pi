## Diff summary

### external-editor.ts (7 issues fixed)
1. `tokenizeCommand` replaced with regex tokenizer that handles `"..."`,
   `'...'`, and bare tokens, and strips surrounding quotes + unescapes `\"`/`\'`.
2. Windows spawn block switched from `shell: true` + manual backslash escaping
   to `shell: false` with token array (single `spawn(editor, [...editorArgs,
   filePath], { shell: false })` for both Windows and POSIX).
3. Silent `child.on("error", () => resolve(null))` replaced with logging:
   `console.error(\`[external-editor] spawn error: ${err.message}\`)`.
4. `mkdtempSync(join(tmpdir(), "pi-editor-"))` → uses
   `crypto.randomUUID()` for collision resistance.
5. "Launching external editor" message now shows only `tokens[0]` (the
   executable), not the full command — avoids leaking sensitive args.

### vitest.config.ts (2 issues fixed)
6. `exclude` array dropped redundant `**/node_modules/**` and `**/.git/**`
   (vitest defaults cover them); kept `**/dist/**` explicit (copied .test.ts
   files from PR #923).
7. Added comment above `server.deps.external` explaining why
   `@silvia-odwyer/photon-node` is excluded (native WASM binding; vite SSR
   cannot bundle native modules).

### external-editor.test.ts (test fixture update, required)
- `quoteIfNeeded` no longer double-escapes backslashes. The backslash escaping
  was specifically required for the prior `shell: true` cmd.exe-mediated spawn,
  which was the very issue the production change fixes. With `shell: false`,
  Node's `child_process.spawn` passes the path directly to `CreateProcessW`,
  which handles spaces natively — no shell escaping needed.
