## Gate K — `bun run --cwd packages/coding-agent build:binary`

Exit: 1 (promote-binary.mjs path bug, pre-existing, not in unit-5 scope)

```
$ bun --cwd ../tui run build && ... && bun --bun run build && bun build --compile ... --outfile dist/pi && bun --bun run copy-binary-assets && bun --bun run build:promote
[1.725s]  bundle  2715 modules
[2.088s] compile  dist/pi.exe
$ shx cp package.json dist/ && ...
$ bun ../../scripts/promote-binary.mjs
ENOENT: no such file or directory, copyfile '...\packages\coding-agent\dist\pi.exe' -> 'C:\dev\packages\coding-agent\dist\pi.exe'
error: script "build:promote" exited with code 1
error: script "build:binary" exited with code 1
```

Despite the promote-step failure, the binary is fully built and runnable
in the worktree:

```
$ ./packages/coding-agent/dist/pi.exe --version
pi 0.84.5 [bramburn]
```

`promote-binary.mjs` computes the main-checkout path as
`resolve(repoRoot, "..", "..")`, which yields `C:\dev` instead of the actual
`C:\dev\pi`. This is a pre-existing path-computation bug that affects every
worktree under `C:\dev\.worktrees\`, not just this one, and predates the
unit-5 changes. The fix would be to use `git rev-parse --git-common-dir`'s
parent directory; not in unit-5 scope.
